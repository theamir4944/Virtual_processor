# 1. Введение в Virtual_Processor

В рамках проекта Virtual_Processor был реализован виртуальный, алгоритмически-полный процессор.

Работа процессора состоит из 2-х (а вообще говоря, из 3-х) действий:

(1) - Генерация «общих» файлов для ассемблера и самого процессора

(2) - Перевод кода в набор машинных команд с помощью asm'а

(3) - Непосредственно выполнение программы процессором



# 2. Вычислительная полнота

Процессор считается **алгоритмически полным**, если на нём можно реализовать какую-либо универсальную вычислительную модель. 
То есть: если у него достаточно памяти и времени, он способен выполнить любую вычислимую задачу.


Как это связано с архитектурой:

(1) - **Условные переходы и циклы** (Без них нельзя реализовать произвольные алгоритмы)

(2) - **Доступ к произвольной ячейке памяти** (Адресная память)

(3) - **Базовые операции** - арифметика (Этого хватает, чтобы собрать любую логику)

(4) - **Возможность эмуляции** (На любом современном процессоре можно эмулировать другую машину Тьюринга или даже другой процессор)



# 3.1. Требования и сборка + запуск

Для запуска программы потребуется компилятор языка **C/C++** (К примеру, g++/clang++)

Также потребуется библиотека **raylib**, чтобы выводить на экран оперативную память (в данном проекте таким образом была реализована видеопамять)

Если этой библиотеки нет, её можно установить, к примеру, с помощью **MSYS2 UCRT64** командой
``` bash
pacman -S mingw-w64-ucrt-x86_64-raylib
```


Файлы generation_file.cpp ; asm.cpp ; spu.cpp следует расположить в одной папке

В этой же папке следует расположить файлы stack_operations.cpp , stack_logging.cpp и log-файл для корректной работы стека (это важно, так как стек является основой для процессора)

Файлы стека можно найти [в одном из предыдущих проектов](https://github.com/theamir4944/It-s-STACK)

И в этой же папке следует расположить txt-файл с кодом (Допустим, это файл fib_numbers.txt)

После этого потребуется ввести несколько команд в терминале:

Компиляция файла-генератора (см 1.1)
``` bash
g++ .\generation_file.cpp -o generation_file.exe
```

Запуск файла-генератора с указанием названий выходных файлов
``` bash
.\generation_file.exe .\general.cpp .\vm_general.cpp
```
! Если не указать названия выходных файлов, они будут названы по умолчанию a.cpp и b.cpp

Компиляция asm'а
``` bash
g++ .\asm.cpp -o asm.exe
```

Запуск asm'а
``` bash
.\asm.exe .\fib_numbers.txt
```
! На этом этапе должен сформироваться файл out.bin - это файл с бинарным кодом, с которым как раз и должен работать процессор

Если требуется посмотреть содержимое bin-файла, советую делать это через hex-редактор (например, через Hex Editor от microsoft)

Компиляция процессора
``` bash
g++ .\spu.cpp -o spu.exe -lraylib -lopengl32 -lgdi32 -lwinmm -lm
```
! Обратить внимание на флаги, их нужно указывать для корректной работы raylib

Запуск процессора
``` bash
.\spu.exe out.bin
```



# 3.2. Упрощение сборки и запуска

Нетрудно заметить, что для запуска программы нужно выполнить немало действий

**Решение этой проблемы существует**

Можно воспользоваться powershell-файлом process_start.ps1 (поместить его в папку с проектом и запустить), все перечисленные команды запуска выполнятся сами

Однако, **raylib** установить всё же придется
